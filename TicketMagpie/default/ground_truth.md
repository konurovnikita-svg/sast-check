• Insecure Direct Object References (IDOR): Хрестоматийная ошибка в логике билетов. При просмотре или скачивании купленного билета (например, по URL вида /tickets/view?id=1001) приложение не проверяет, принадлежит ли этот билет авторизованному пользователю. Меняя id (1002, 1003...), можно просматривать и скачивать чужие билеты.
• SQL-инъекции (SQLi): Формы поиска билетов, фильтрации по датам или категориям не используют параметризованные запросы PreparedStatement. Прямая конкатенация строк позволяет внедрить SQL-код, обойти авторизацию или выгрузить всю базу данных пользователей с их хэшами паролей.
• Cross-Site Scripting (XSS): Поля ввода данных при оформлении билета (имя, фамилия, комментарии к заказу) не проходят фильтрацию и экранирование. Злоумышленник может внедрить туда JavaScript-код (Stored XSS). Когда администратор зайдет в панель управления, чтобы проверить заказы, этот скрипт выполнится в его браузере и может украсть его административную сессию.
• Ошибки бизнес-логики (Business Logic Flaws): Специфичные уязвимости для e-commerce систем. Например, возможность передать отрицательное количество билетов в корзине (-5) или изменить цену билета прямо в HTTP-запросе перед отправкой на сервер, что позволяет «купить» билет бесплатно или даже получить баланс в плюс.
• Раскрытие системной информации (Information Disclosure): При вводе некорректных данных или провокации ошибок приложение возвращает пользователю подробный Stack Trace фреймворка Spring, раскрывая внутреннюю структуру проекта и версии библиотек.
