• A1: Injection (Инъекции)
	• SQL Injection: Классический обход авторизации (Bypass Login) на странице входа с помощью инъекции типа anything' OR '1' ='1.
	• Command Injection: Возможность выполнять системные команды ОС через поле ввода домена (например, отправка строки вида google.com && ifconfig) или через небезопасный запуск встроенной функции Python eval().
• A2: Broken Authentication (Сломанная аутентификация)
	• Брутфорс OTP: На этапе подтверждения входа через 3-значный одноразовый пароль (OTP) полностью отсутствует ограничение частоты запросов (Rate Limiting). Это позволяет злоумышленнику за секунды подобрать код перебором с помощью утилит типа Burp Suite.
• A3: Sensitive Data Exposure (Раскрытие конфиденциальных данных)
	• Debug Mode Enabled: В конфигурационном файле Django settings.py намеренно оставлен флаг DEBUG = True. При вызове любой системной ошибки приложение выводит на экран структуру каталогов, переменные окружения и секретные ключи.
• A4: XML External Entities (XXE)
	• Инъекция в XML-парсер: Использование небезопасных библиотек для обработки XML-данных (комментариев), что позволяет злоумышленнику внедрить вредоносные DTD-сущности и прочитать файлы с сервера (например, /etc/passwd).
• A5: Broken Access Control (Нарушение контроля доступа)
	• Подмена сессий и Cookie: Доступ к панели администратора можно получить путем простой модификации сессионных кук или подмены заголовка User-Agent.
• A6: Security Misconfiguration (Неправильная настройка безопасности)
	• Уязвимость к атакам на Host-заголовки: Приложение доверяет любым входящим HTTP-заголовкам X-Host, что позволяет осуществить подмену хоста (например, передав X-Host: admin.localhost:8000).
• A7: Cross-Site Scripting (XSS)
	• Межсайтовый скриптинг: Возможность внедрять HTML-теги и JavaScript-скрипты в текстовые поля, которые затем отображаются другим пользователям без предварительной фильтрации и экранирования.
• A8: Insecure Deserialization (Небезопасная десериализация)
	• Атака на Pickle: Использование встроенного в Python модуля pickle (или base64/pickle cookie) для сериализации объектов. Изменение сериализованного бита "admin" на стороне клиента приводит к выполнению произвольного Python-кода на сервере при десериализации.
• A9: Using Components with Known Vulnerabilities
	• Уязвимые библиотеки: В файле requirements.txt зафиксированы старые версии популярных Python-пакетов (например, PyYAML или Pillow), содержащие известные критические уязвимости для удаленного выполнения кода (RCE).
