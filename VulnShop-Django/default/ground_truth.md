Намеренные ошибки в коде магазина (OWASP Top 10)

• SQL Injection: Запросы построены через прямую конкатенацию строк (например, Manager.raw()) вместо безопасных фильтров ORM, что позволяет читать базу данных.
• XSS (Межсайтовый скриптинг): В шаблонах отзывов к товарам использован фильтр |safe или тег {% autoescape off %}. Злоумышленник может внедрить JavaScript в поля комментариев.
• IDOR (Нарушение контроля доступа): На эндпоинтах /orders/<id>/ нет проверки request.user == order.user. Любой авторизованный пользователь может просматривать чужие заказы, меняя ID.
• Mass Assignment: Модели создаются напрямую из request.POST.dict() без валидации через ModelForm. Покупатель может передать параметр is_staff=True и получить права администратора.
• Security Misconfiguration: В settings.py оставлен флаг DEBUG = True, который при ошибках раскрывает системные пути, конфигурацию и SECRET_KEY.

Критические уязвимости самого Django (CVE)

• CVE-2025-64459 (SQL Injection): Критическая уязвимость в ORM (CVSS 9.1). Передача словаря с системными ключами _connector в методы filter() изменяет логику SQL-запроса и обходит авторизацию.
• CVE-2025-57833 (FilteredRelation SQLi): Недостаточная валидация параметров при совместном использовании QuerySet.annotate() и FilteredRelation позволяет внедрять вредоносный SQL-код.
• CVE-2025-64458 (DoS на Windows): Избыточная нагрузка на процессор при обработке тяжелой Unicode-нормализации внутри функций редиректа, приводящая к отказу сервера в обслуживании.
