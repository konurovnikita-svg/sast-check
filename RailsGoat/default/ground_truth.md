• A1: Injection (Инъекции)
	• SQL Injection: Использование небезопасных методов ActiveRecord (например, построение запроса через прямую интерполяцию строк where("name = '#{params[:name]}'") вместо плейсхолдеров). Это позволяет читать базу данных в обход авторизации.
	• Command Injection: Передача пользовательского ввода напрямую в методы системного вызова (например, system() или с помощью обратных кавычек ` `). Злоумышленник может выполнить команды в терминале ОС сервера.
• A2: Broken Authentication (Сломанная аутентификация)
	• Небезопасное восстановление пароля: Логика сброса пароля содержит дефекты, позволяющие перехватить токен сброса или изменить пароль чужого пользователя.
	• Отсутствие Rate Limiting: Уязвимость к брутфорсу учетных записей.
• A3: Sensitive Data Exposure (Раскрытие конфиденциальных данных)
	• Утечка файлов конфигурации: В репозитории намеренно оставлены жестко закодированные секретные ключи (secret_key_base в secrets.yml). Злоумышленник может использовать их для подделки сессионных кук.
• A4: XML External Entities (XXE)
	• Небезопасный парсинг XML: Использование старых версий библиотек (например, парсера Nokogiri), где включена обработка внешних сущностей, что позволяет читать файлы с сервера.
• A5: Broken Access Control (Нарушение контроля доступа)
	• Mass Assignment (Массовое присвоение): Классическая уязвимость старых Rails-приложений. Контроллеры принимают параметры без фильтрации (например, через User.new(params[:user])), что позволяет злоумышленнику передать в HTTP-запросе поле admin: true и повысить свои привилегии.
	• IDOR: Доступ к чужим профилям или счетам путем прямого перебора идентификаторов в URL (например, /users/5/documents).
• A7: Cross-Site Scripting (XSS)
	• Обход экранирования Rails: Использование методов .html_safe или raw() на невалидированном пользовательском вводе, что приводит к хранимому и отраженному межсайтовому скриптингу.
• A8: Insecure Deserialization (Небезопасная десериализация)
	• Атака на Marshal / YAML: Использование небезопасных методов десериализации (например, YAML.load вместо YAML.safe_load). Позволяет злоумышленнику передать вредоносный сериализованный объект и добиться выполнения произвольного Ruby-кода (RCE).
